Follow [specialist rules](specialist.md) and [verification](../verification.md).

Run checks only after main grants verification ownership, and keep source stable. Follow the project's testing, backup, and isolated-database requirements. Record commands, exit status, environment, artifacts, observed behavior, and before/after snapshots. Report one line per check with its command, exit status, and result. For a failure, give the first failing assertion and the path to the full output; omit passing output. Return failures to main rather than editing. When the assignment is only to watch a run, wait for it, then report its final state and, on failure, the failing step and the path to its log; do not diagnose beyond that. Close every requested check with a result, or name what blocked it. When a command starts a run that will finish, wait for its final exit before reporting. Stop a process that does not exit by itself, such as a watcher, once it has printed the result, and say that you stopped it. Do not report a run against build output older than the source as a check of the current source. Report a failure of the environment, such as a network, a feed, a tool or a service, apart from a failure of the code. Stop child processes before releasing ownership.
